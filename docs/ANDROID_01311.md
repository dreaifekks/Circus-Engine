# Android 0.13.11：接入 D.C.II 2006 原版

安装 `build/android/circus-core-debug.apk`（`versionCode` 30，`0.13.11-android-dev`）。
沿用已有包名、签名和其余版本的存档格式，可以覆盖安装，不要卸载或清除应用数据。

## 新增

D.C.II 2006 原版（MES 版本 13155／6755／12643，profile `dc2-3363`）现在可以进入并游玩。
它在 D.C.II P.C 之外单独识别，不会与 P.C 的 22377／39273 混淆。

| 项目 | 状态 |
|---|---|
| 启动 → 标题 → 正文 | 可运行 |
| 存读档（`SAVE.mes`／`LOAD.mes`） | 可运行，槽位标题与角色图标正确 |
| 系统菜单 `ADVMENU.mes` | 可运行，含返回正文 |
| CG Mode `anz_00..11` | 可运行，七个人物页签、11 页、未解锁显示占位框 |
| 场景回想 `kaiso_00..02` | 可运行，缩略图受素材缺失影响（见下） |
| 闹钟设定 `meza_nin_*`／`meza_obk_*` | 可运行，三档选择后转入对应剧情脚本 |
| 整条路线到片尾 | **未验证** |

## 三处解释器改动

- **`0x50` 按钮文字**。原先当成「消耗一条字串记录但效果未知」，全库 4685 条全被丢弃，
  CG Mode 与回想页的标题因此空白。实际是 `415124` 读两个 word 加尾随字串，调 `40DD50`
  往上一个按钮的空 sprite 槽里追加文字（宽 `14*字长+1`、高 `0x1D`）。2006 版给每条标签
  加了 `@s` 前缀，原生的宽度算上了它但不显示，所以剥字符、保宽度。
- **`0x24` 资源句柄**。`414B9D` 按参数切到三个固定句柄（0／2／3，没有 1），不是 P.C 那套
  连续的 `21+参数` 槽位。全库只有 `start.mes` 用一次，视觉上无差异，但语义已改对。
- **语音名 `--`**。闹钟脚本在关掉 BGM 和音效后紧跟 `34 dm.audio.voice "--"`，表示停语音声道。
  旧实现把它当资源名去开 `AdvData/--.PCM`，整帧失败。

## 音频与素材

- SE `222..229`（闹钟音床）在原版里是裸 RIFF/WAVE，其余 128 个是 XPCM；解码器现在两种容器都认。
- 缺素材不再中断整帧：对应槽位留空，名字记进 `missingImages`。
  本机 DC2 只有 `SYSTEM/scene_sam.CRX`，而脚本要 `scene_sam_01..30`，
  所以场景回想的缩略图本来就画不出来。

## 已知显示问题（非缺陷）

`kaiso_01`／`kaiso_02` 的标题显示为乱码，例如 `攷聖側側修傳僞倀`。这些页面的脚本仍是原始
Shift_JIS（该处字节是 `83 76 83 8d ...`，即「プロローグ」），而这套是蘑菇 V9.9 汉化版，
文本已被改写成 GBK。逐字节比较 `dc2.exe` 与 `dc2.old`：补丁只把 `3c a0 72 08` 改成
`3c fe eb 08`（让 >0x80 一律按双字节走），字形表按 GBK 顺序重排 ——
也就是说未翻译的日文在**原版补丁里同样显示为乱码**，这里没有额外损失。

- 十二个 `anz_*`、三个 `kaiso_*`、八个 `meza_*` 页面渲染和控件集合正确，翻页／返回／退回标题正常。
- D.C.II P.C 的启动走查行为不变。
